# Pelican riding a bicycle

Final output: pelican.svg

Create one polished, self-contained, hand-authored SVG illustration of a pelican riding a bicycle. Work as an equal peer in this swarm: name yourself, read the shared conversation, choose a useful role, coordinate ownership, and improve the shared canonical artifact. Contributors should divide illustration, geometry, rendering, critique, and verification work instead of producing competing final files.

The pelican should read unmistakably as a pelican, with a long bill, large throat pouch, substantial white/gray body, and webbed feet. Its body should sit over the saddle; wings should visibly reach the handlebars and feet should meet the pedals. Draw a recognizable bicycle with two spoked wheels, connected frame triangles, saddle, handlebar assembly, crank, pedals, and chain. Compose an intentional scene with a ground plane and coherent palette. Resolve overlaps so the rider and bicycle occupy the same physical space.

Publish a rough but complete pelican.svg before approximately 15% of the shared budget has been spent. Continue refining that file using claims and revision-aware writes. Keep supporting renders and measurements under verify/. Explain contributions and evidence in shared threads. No external resources or raster imagery may be embedded in the final SVG.

## Definition of Done

- The canonical pelican.svg contains a complete, legible pelican riding a complete bicycle and opens without errors or network dependencies.
- The anatomy, riding posture, wheel/frame geometry, physical contact points, layering, composition, and palette have all received explicit review.
- Render the SVG with Chromium to verify/pelican.png after meaningful revisions. Inspect the rendered image; a file existing alone is insufficient evidence.
- Record at least two quantitative critiques, including coordinates or measurements for wheel circularity/relative size, saddle-to-body alignment, bill/pouch proportions, or wing-to-handlebar and foot-to-pedal contact. Apply justified corrections and record their outcome.
- At least one peer must deliberately try to disprove readiness and report the strongest defects found, with evidence and resolution.
- Two independent peers must review the same final file hash and publish signoffs referring to the rendered result and the criteria above. Keep a contribution record in the shared conversation.
- Retain one canonical final SVG. Put supporting material below verify/ rather than leaving competing top-level candidates. Call done only after recording concrete evidence for your contribution and the shared final result.
